# Frontend Fidelity Reconstruction

## Purpose

Builds production frontend implementations from approved references with explicit precedence, responsive rules, and visual-regression requirements.

## Invoke when

- approved references should become a working frontend

## Do not invoke when

- reference authority is ambiguous and cannot be resolved

## Inputs

- approved reference pack
- blueprint/topology
- assets
- framework constraints

## Outputs

- frontend scaffold/implementation
- asset bindings
- responsive behavior
- visual regression report

## Method

1. Freeze the source-of-truth reference order.
2. Implement structural shell and topology before decorative motion.
3. Use actual supplied assets and tokens before approximating.
4. Bind real controls to real states or truthful unavailable states.
5. Implement responsive structural transformations, not only scaling.
6. Add loading/error/empty states and accessibility behavior.
7. Compare rendered output against references at representative viewports.
8. Iterate only on measured fidelity gaps and implementation defects.

## Quality gates

- structural fidelity precedes animation
- no invented product behavior
- responsive transformations preserve task state
- visual regression evidence exists before fidelity claim

## Failure behavior

If required evidence, authority, runtime capability, or source material is missing, return the missing dependency or blocked state explicitly. Do not fabricate execution, verification, or source-of-truth evidence.
