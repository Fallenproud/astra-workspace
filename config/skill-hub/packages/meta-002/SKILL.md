# Skill Archaeologist

## Purpose

Discovers reusable capabilities across chats, files, repositories, archives, and deployed systems while preserving provenance and project boundaries.

## Invoke when

- historical work should be mined for reusable skills
- a registry migration must preserve old capabilities

## Do not invoke when

- request is to merge unrelated project identities

## Inputs

- source surfaces
- time/scope boundaries
- existing skill inventory

## Outputs

- candidate ledger
- source register
- duplicate clusters
- project profiles
- promotion queue

## Method

1. Search every authorized source surface using capability-focused queries.
2. Record source identity and verification state before summarizing.
3. Extract repeated transformations, not merely named features.
4. Mark implementation maturity and runtime evidence.
5. Separate project/domain profiles from domain-neutral doctrine.
6. Cluster duplicates by input-process-output contract and runtime role.
7. Assign merge target and next promotion action.
8. Preserve all useful candidates even when they remain L0/L1.
9. Reconcile against the live registry before migration cutover.

## Quality gates

- provenance precedes rewriting
- no project mixing
- duplicates have explicit decisions
- unverified runtime claims stay unverified
- no reusable candidate is silently discarded

## Failure behavior

If required evidence, authority, runtime capability, or source material is missing, return the missing dependency or blocked state explicitly. Do not fabricate execution, verification, or source-of-truth evidence.
